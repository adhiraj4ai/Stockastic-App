# Next-Day Trading Plan ("Tomorrow's Plan") — Design

**Date:** 2026-06-10
**Status:** Approved (design review with user)

## Problem

Stockastic computes nearly everything a trader needs — 10 signal engines, opportunity
ranking with live-validated trust tiers, market regime, smart-money accumulation,
lag-correlation studies — but it is scattered across ~50 routes. No feature answers
**"what should I do tomorrow?"** in one place at the moment the decision is made
(evening after close / morning before NEPSE opens).

## Solution

A precomputed daily plan with four sections, delivered as a dedicated page (`/plan`)
plus a "plan ready" notification:

1. **Regime + top confluence picks** — market regime banner; 3–5 ranked picks with a
   cross-engine confluence score and an entry-validity (freshness) filter.
2. **Your positions & watchlist actions** — holdings near SL/TP, signals flipped
   against holdings, watchlist levels crossed or near.
3. **Catalyst calendar** — upcoming book-close / dividend-announcement dates within
   14 days, flagged on picks and holdings.
4. **Historical analogs** — per pick: median forward 1/3/5-day return, win rate, and
   sample size for similar past setups on that symbol.

## Architecture

One **global plan** per trading day, generated by a celery task chained after
`generate_all_signals_task` and episode evaluation (slots into the existing daily
pipeline from the Plan 5 hygiene work). A thin **per-user overlay** is computed at
read time from indexed queries — no per-user plan rows, no overlay staleness.

```
evening pipeline:  ingest → generate_all_signals → evaluate_episodes → generate_daily_plan
                                                                            │
                                                              DailyTradingPlan (1 row/day)
                                                                            │
GET /api/plan/today/  ──────  global payload  +  user overlay (computed live)
```

## Data model

New model `DailyTradingPlan` (in `stocks/models/`):

| Field | Type | Notes |
|---|---|---|
| `date` | DateField, unique | Trading date the plan is FOR (next session) |
| `generated_at` | DateTimeField | |
| `regime` | CharField | RISK_ON / NEUTRAL / RISK_OFF (from `market_regime.py`) |
| `breadth` | FloatField | % of universe above 200-day SMA |
| `payload` | JSONField | `{picks, exits, catalysts, market_context}` |

Follows the existing JSON-payload pattern (`SignalEpisode.metadata`,
`PortfolioActionDraft.payload`). Plan history is auditable for free.

## Computation pieces (all at generation time)

### 1. Confluence score — new `stocks/services/confluence.py`

For each symbol with ≥1 ACTIVE BUY `SignalEpisode`:

- **Engine agreement**: count of distinct ACTIVE BUY sources; ACTIVE SELL or
  DISTRIBUTION_ALERT episodes on the same symbol *subtract*.
- **Opportunity score**: the existing opportunity engine's
  edge × significance × trust × regime score where available.
- **Accumulation context**: price vs top-broker WAC and 5-day institutional net
  (already in episode metadata).
- **Sector momentum**: sector `acc_intensity` from the sector-rotation service.

Output: 0–100 plus a per-component breakdown for explainability. The UI never shows
a bare number. Exact component weights are an implementation detail to be tuned
against fixtures; starting point: engine agreement 35%, opportunity 35%,
accumulation 20%, sector 10%. DIVERGENT-trust producers are excluded from picks
entirely (consistent with the opportunity engine's sink-to-bottom rule).

### 2. Freshness / entry validity

A pick is "actionable tomorrow" iff:

- latest close ∈ `entry_price ± 1 × ATR(14)`, and
- `last_signal_date` within 5 trading days.

Out-of-zone picks are labeled (`EXTENDED +6.2%` / `STALE`) rather than silently
dropped, but only IN_ZONE picks qualify for the top-5. Thresholds (`1×ATR`,
5 days) are constants in the service, not user settings, for v1.

### 3. Historical analogs

Per pick symbol: fingerprint today's setup as
(10-day accumulation-momentum bucket, RSI band, regime), scan that symbol's
history using the corporate-action-adjusted price loader from the backtest
harness, and compute forward 1/3/5-day return distribution (median, win rate, n).
**If n < 5, show nothing** — no fake base rates. Computed at generation time and
stored in the payload (never at request time).

### 4. Catalyst calendar

`Dividend.book_close_date` and `FinancialReport` dividend-announcement dates
within the next 14 days, market-wide. Each pick carries its own catalyst flag;
the user overlay flags catalysts touching holdings/watchlist.

## Per-user overlay (read time)

Three indexed queries against existing tables:

1. **Positions near action**: holdings where latest close is within 2% of
   `stop_loss_price` or any `target_price` tier.
2. **Signal flips**: ACTIVE SELL episodes on held tickers.
3. **Watchlist triggers**: watchlist `target_price`/`stop_loss_price` crossed or
   within 2%.

Users with no portfolio get the market half only.

## Generation task

`generate_daily_plan_task` (celery), chained after signal generation + episode
evaluation in the daily beat schedule. Idempotent per date (upsert on `date`).
Failure handling: log to `DataUploadLog`; the previous plan stays served with a
stale banner. NEPSE holidays (no new price data): skip generation.

## API

- `GET /api/plan/today/` → latest plan payload + user overlay.
- `GET /api/plan/?date=YYYY-MM-DD` → historical plan (global only, no overlay).
- Gated by a tier-permission module key (same mechanism as `signals_tab` etc.).

## Notification

After the plan persists, create a `DAILY_PLAN_READY` notification (new type in the
existing enum) with `redirect_url=/plan`, for users whose tier includes the module.
Reuses the existing notification machinery unchanged.

## Frontend

- New route `/plan` (authenticated), full-width, sidebar entry directly under
  Home (label "Tomorrow's Plan").
- Page order: regime banner → pick cards (score + component chips, entry-zone
  status, analog base rate, catalyst flag, link to `/ticker/[symbol]`) →
  "Your actions" section → catalyst strip → date picker for past plans.
- **Honest empty state**: RISK_OFF with no qualifying picks renders
  "No high-trust setups for tomorrow — breadth is 31%, consider sitting out"
  instead of padding with weak picks. No-trade advice is a feature.
- Stale banner when serving a previous day's plan after a generation failure.

## Testing

- Unit tests: confluence scorer (episode fixtures incl. conflicting-source case),
  freshness filter (in-zone / extended / stale), analog engine on seeded adjusted
  prices (incl. n<5 suppression).
- API tests: overlay logic (near-SL, signal-flip, watchlist-cross), permission
  gating, history endpoint.
- Frontend: pick-card rendering (score breakdown, entry status, analog, catalyst),
  empty state, stale banner.

## Out of scope (v1)

- Position-sizing suggestions (bridge to `TradePlan` drafts) — natural v2.
- EOD wrap-up companion page.
- User-tunable thresholds (ATR multiplier, freshness window, near-SL %).
- Intraday plan updates; the plan is an end-of-day artifact.
